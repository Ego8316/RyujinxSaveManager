# Ryujinx storage provider

The user will select the save root, commonly `Ryujinx/bis/user/save/`. A future `RyujinxStorageProvider` will enumerate containers without mutating them and return `DiscoveredSave` records with provider ID, container path, and optional Title ID, user ID, and display label. IDs and labels must be optional because layouts and metadata availability may vary. `ExtraData0` may help identification; its layout is not assumed here. The scanner must accept a provided `Path`: automatic path discovery can be offered where reliable, while manual selection and later remembering the selection remain available. A path under WSL such as `/mnt/c/Users/.../` may point to a Windows volume, so filesystem behavior cannot be inferred solely from the Python process's OS.

Discovery must separate emulator metadata from game payload parsing. It should tolerate unreadable or malformed entries by reporting diagnostics, avoid traversing links outside the selected root, and never treat a directory name as a verified Title ID without evidence. Exact Ryujinx directory traversal and metadata interpretation need fixture-backed research before implementation. Future providers can share the normalized model without inheriting Ryujinx assumptions.
