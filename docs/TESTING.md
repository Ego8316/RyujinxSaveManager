# Testing strategy

From WSL or another Linux development environment, activate a Python 3.12+ virtual environment, install `.[dev]`, and run `python scripts/check.py`. This runs Ruff lint, Ruff format check, strict mypy, and pytest with terminal missing-line coverage at a minimum of 80%. Run `ruff format .` to apply the canonical formatter. CI runs those same checks on Ubuntu and Windows with Python 3.12; no display server, Ryujinx installation, keys, or real saves are needed. The headless Qt smoke test still loads PySide6's native libraries: on Ubuntu, install `libegl1` if importing `PySide6.QtWidgets` fails because `libEGL.so.1` is missing. CI installs that package on its Linux runner.

The current tests exercise format-neutral diff output, plugin registration, read-only directory discovery, bounded `ExtraData` reads, metadata disagreement and size diagnostics, Account/Device/BCAT Application ID decoding, unknown type preservation, and headless UI presentation. Future game-format parser tests should use synthetic fixtures wherever possible and cover signatures, accepted sizes, exact offset reads/writes, byte preservation, nibble neighbors, endianness, and checksums. A key regression pattern is: load fixture, edit one known field, compare bytes, and assert only the documented field and integrity offsets changed.

Provider tests need synthetic directory trees for missing metadata, links, unreadable files, and ambiguous IDs. Backup tests need size/hash verification, all relevant files, stale-source detection, failed copy, failed write, interruption, rollback, and Windows atomic-replacement behavior. Use `tmp_path` and Python filesystem APIs; do not assume POSIX rename semantics, case sensitivity, or a specific path separator. Plugin tests need detection conflicts and false positives. Diff tests need equal inputs, replacements, and length changes. Real or copyrighted saves must not enter the public suite without an appropriate right to distribute them; private fixtures belong outside version control.
